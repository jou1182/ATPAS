# مسرد مصطلحات ATPAS — لغة المجال الموحدة

**آخر تحديث**: 29 أغسطس 2026
**الغرض**: تعريف دقيق وموحّد لمصطلحات المجال — أي وكيل أو مطور يستخدم هذه المصطلحات بنفس المعنى. لا يوجد تنفيذ تقني هنا (راجع `ARCHITECTURE_AR.md` لذلك).

---

## المصطلحات الأساسية

| المصطلح | التعريف | ملاحظات |
|---|---|---|
| **العرض الفني** (Proposal) | الملف النهائي Word المقدَّم إلى جهة مالكة — نتيجة تركيب أنشطة متعددة في مستند واحد | يتكون من: غلاف + فهرس + أقسام أنشطة + هوية الجهة |
| **الكود الفني** (Activity Code) | الوحدة الأساسية للعمل — نشاط قابل للتنفيذ في مشروع إنشائي | الصيغة: `NNN-PHASE-VARIATION` (مثال `001-SUR-BASE`) |
| **النشاط** (Activity) | المحتوى الفعلي لكود — ملف `.docx` في `templates/source_documents/` | اسم الملف == `{code_id}.docx` |
| **القسم** (Section) | وحدة العرض في الملف النهائي — عنوان H1 (`الاسم — الكود`) + محتوى النشاط | كل كود مختار = قسم واحد |
| **الفئة** (Category) | التصنيف الأوسع للأكواد — 001 تحضيرية → 005 تسليم | من `master_config.json → code_ranges` |
| **المرحلة** (Phase) | تصنيف فرعي داخل الفئة — SUR/PRM/EXC/PIP/TST/BKF/RST/HND | من `master_config.json → phases` |
| **التنويع** (Variation) | تمييز كود عن آخر في نفس المرحلة — BASE/FINE/OPEN/TUNNEL | من `codes_registry.json → variations` |

## أصحاب المصلحة والتخصيص

| المصطلح | التعريف | كيف يخصّص الإخراج |
|---|---|---|
| **الجهة المالكة** (Owner) | الجهة الحكومية/الخاصة التي يُقدَّم لها العرض — 20 جهة | 4 طبقات: فلترة الأكواد، النمط البصري، اسم الغلاف، قواعد المشروع |
| **المشروع** (Project) | نوع البنية التحتية — صرف صحي/مياه/أسفلت/طرق/إنشاءات/نقل مياه — 6 مشاريع | يحدد الأكواد المتاحة + `activity_sequence` |

## آلية التركيب

| المصطلح | التعريف |
|---|---|
| **التركيب** (Stacking/Composition) | نسخ جسم كل ملف نشاط `.docx` إلى الملف الهدف على مستوى OOXML — لا دمج نصي |
| **صفحة الفاصل** (Category Divider) | صفحة بعنوان الفئة ووصفها تُدرج قبل قسم الكود الأول من كل فئة (001–005) — تُحسب في `estimate_pages` (+1 لكل فئة إضافية) |
| **مكتبة الأنشطة** (Content Library) | مجلد `templates/source_documents/` + سجل `content_registry.json` + حالات الاعتماد |
| **اعتماد المحتوى** (Content Approval) | حالة موثّقة (بـ SHA-256) لكل ملف نشاط في `templates/content_approval.json` — المحتوى المعتمد فقط يُعد جاهزاً للتسليم |

## التبعيات والترتيب

| المصطلح | التعريف |
|---|---|
| **التبعية** (Dependency) | كود يجب أن يكون في العرض قبل/مع كود آخر — `dependencies` في الكود |
| **التبعية البديلة** (Alternative Dependency) | "أي من مجموعة" — المنطق في `engine/rules.py` **وحده** (AGENTS.md قاعدة 11) |
| **الترتيب التسلسلي** (Sequence Order) | ترتيب عرض الأقسام — `sequence_order` في الكود |
| **جدول الكميات** (BOQ) | جدول كميات من منافسة (Excel) — يُستورد للترتيب وليس للأسعار |

## عناصر البيانات

| المصطلح | التعريف |
|---|---|
| **النمط الجاهز** (Preset) | وصفة عرض كاملة: مشروع + جهة + قائمة أكواد — من `presets.json` |
| **معرفة المشروع** (Project Metadata) | ملف `<project_id>_project_metadata.json` — ترتيب الأقسام، الإلزامات، قواعد الجهات، النماذج النموذجية |
| **قواعد الجهة** (Owner Specification) | ملف `metadata/owner_specifications/<owner>.json` — أكواد إلزامية/ممنوعة للـ Validator |
| **هوية الجهة** (Owner Style) | ملف `templates/style_templates/<owner>_style.json` — خطوط/ألوان/هوامش/ترويسة/تذييل |

## مصطلحات الإخراج

| المصطلح | التعريف |
|---|---|
| **مسار التدقيق** (Audit Trail) | سجل JSON لكل بناء في `output/audit_trail/` — من `engine/logger.py` |
| **فهرس الأرشيف** (Archive Index) | قاعدة SQLite (WAL) لفهرسة سجل العروض السابقة — بحث فوري — `utils/archive_index.py` |
| **النسخة التجريبية** (Trial) | ترخيص يوم واحد بعلامة مائية في الملف النهائي — مرة واحدة لكل جهاز |

## قواعد استخدام المسرد
1. **استخدم المصطلح الدقيق** — "كود" وليس "عنصر"، "قسم" وليس "جزء"، "تركيب" وليس "دمج".
2. **لا تخترع مرادفات** — إذا وجدت تعارضاً مع تعريف هنا، ناقشه قبل التعديل.
3. **كل مصطلح له معنى واحد** — إذا بدأ المعنى يتشعب، حدّث المسرد (وليس الكود).
