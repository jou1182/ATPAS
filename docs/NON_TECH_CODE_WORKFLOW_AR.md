# دليل مبسط جدًا لإضافة أو تعديل كود في ATPAS

هذا الدليل مكتوب لشخص لا يملك خبرة برمجية. اتبع الخطوات بالترتيب، ولا تقفز خطوة.

---

## الفكرة ببساطة

كل بند فني في البرنامج اسمه **كود**.

مثال:

```text
001-SUR-BASE
```

البرنامج يقرأ الأكواد من ملف:

```text
codes_registry.json
```

ولو أردت أن يظهر كود جديد في البرنامج، تضيفه داخل هذا الملف.  
ولو أردت أن يكون للكود محتوى Word حقيقي، تضع ملف Word بنفس اسم الكود داخل:

```text
templates/source_documents/
```

---

## قبل أي تعديل

نفذ واحدة من هذه الطرق:

### الطريقة الأسهل

اضغط مرتين على:

```text
نسخة_على_GitHub.bat
```

هذا يحفظ نسخة من آخر حالة على GitHub.

### أو من داخل PowerShell

```powershell
.\backup_to_github.bat
```

---

## متى أضيف كود جديد؟

أضف كودًا جديدًا إذا كان لديك بند فني غير موجود في القائمة، مثل:

- طريقة تنفيذ جديدة.
- اختبار جديد.
- بند تسليم جديد.
- متطلب خاص لجهة مالكة.

لا تضف كودًا جديدًا إذا كان المطلوب مجرد تغيير اسم أو عدد صفحات لكود موجود. في هذه الحالة عدّل الكود الموجود.

---

## شكل الكود الصحيح

الكود يتكون من 3 أجزاء:

```text
الفئة-المرحلة-النوع
```

مثال:

```text
003-PIP-MAIN
```

معناه:

| الجزء | المثال | الشرح |
|---|---|---|
| الفئة | `003` | التركيب والتوصيل |
| المرحلة | `PIP` | أنابيب |
| النوع | `MAIN` | رئيسي |

الفئات المتاحة:

| الرقم | المعنى |
|---|---|
| `001` | الأعمال التحضيرية |
| `002` | الحفر والمخلفات |
| `003` | التركيب والتوصيل |
| `004` | الاختبارات والفحوصات |
| `005` | الإنهاء والتسليم |

## إضافة كود جديد خطوة بخطوة

### 1. افتح ملف الأكواد

افتح:

```text
codes_registry.json
```

ابحث عن:

```json
"codes": {
```

كل الأكواد موجودة داخل هذا الجزء.

### 2. انسخ كودًا مشابهًا

أسهل وأضمن طريقة:

1. ابحث عن كود قريب من نفس النوع.
2. انسخه بالكامل.
3. الصقه في مكان جديد داخل `"codes"`.
4. غيّر القيم المطلوبة فقط.

### 3. نموذج جاهز لكود جديد

استخدم هذا النموذج وعدّل القيم:

```json
"003-PIP-MAIN": {
  "code_id": "003-PIP-MAIN",
  "category": "003",
  "phase": "PIP",
  "variation": "MAIN",
  "activity_name_ar": "تركيب خط أنابيب رئيسي",
  "activity_name_en": "Main Pipeline Installation",
  "project_ids": ["wastewater", "water_supply"],
  "network_types": ["S", "W"],
  "applicable_owners": ["nwc", "makkah"],
  "sequence_order": 50,
  "dependencies": ["001-SUR-BASE"],
  "has_images": false,
  "image_count": 0,
  "page_count": 4,
  "source_document": "003-PIP-MAIN.docx",
  "section_reference": "pipeline_installation",
  "tags": ["pipeline", "installation"],
  "status": "active",
  "created_date": "2026-04-26",
  "last_modified": "2026-04-26",
  "version": "1.0",
  "notes": "كود جديد مضاف يدويًا"
}
```

### 4. انتبه للفواصل

في JSON، كل كود يفصل بينه وبين الذي بعده فاصلة:

```json
},
"الكود-التالي": {
```

لكن آخر كود داخل القائمة لا يكون بعده فاصلة.

هذه أكثر غلطة شائعة.

---

## شرح الحقول ببساطة

| الحقل | ماذا يعني؟ | مثال |
|---|---|---|
| `code_id` | رقم الكود نفسه | `003-PIP-MAIN` |
| `category` | أول 3 أرقام من الكود | `003` |
| `phase` | الجزء الأوسط | `PIP` |
| `variation` | الجزء الأخير | `MAIN` |
| `activity_name_ar` | الاسم الذي يظهر للمستخدم | تركيب خط أنابيب رئيسي |
| `activity_name_en` | الاسم بالإنجليزية | Main Pipeline Installation |
| `project_ids` | المشاريع التي يظهر فيها الكود | `wastewater` |
| `network_types` | نوع الشبكة | `S`, `W` |
| `applicable_owners` | الجهات المالكة التي يظهر معها | `nwc` |
| `sequence_order` | ترتيب ظهور الكود | `50` |
| `dependencies` | أكواد يجب اختيارها قبله | `001-SUR-BASE` |
| `page_count` | عدد الصفحات التقريبي | `4` |
| `source_document` | اسم ملف Word الخاص بالكود | `003-PIP-MAIN.docx` |
| `status` | هل يظهر أم لا؟ | `active` |

## إضافة ملف Word للكود

إذا كان لديك محتوى جاهز للكود:

1. افتح مجلد:

```text
templates/source_documents/
```

2. ضع ملف Word داخله.
3. اجعل اسم الملف مطابقًا للكود:

```text
003-PIP-MAIN.docx
```

4. تأكد أن حقل `source_document` في الكود هو نفس الاسم:

```json
"source_document": "003-PIP-MAIN.docx"
```

إذا لم تضع ملف Word، سيعمل البرنامج لكنه سيستخدم نصًا عامًا بدل المحتوى الحقيقي.

---

## خط ومحاذاة ملف Word الناتج

لا تحتاج إلى ضبط الخط أو اتجاه النص داخل قالب الجهة يدويًا. التطبيق يفرض على كل عرض فني ناتج القاعدة التالية:

```text
Tajawal + RTL + محاذاة يمين
```

هذه القاعدة تطبق على كل الجهات الحالية وأي جهة جديدة تتم إضافتها مستقبلًا. حتى إذا كان ملف Word المصدر أو قالب الجهة يستخدم خطًا آخر، سيحوّل محرك البناء الناتج النهائي إلى Tajawal ومحاذاة يمين.

للتأكد، افتح شاشة **صحة النظام** وابحث عن:

- `خط الإخراج الإجباري`
- `عقد الإخراج`

## تعديل كود موجود

### تعديل الاسم

غيّر:

```json
"activity_name_ar": "الاسم الجديد"
```

### تعديل عدد الصفحات

غيّر:

```json
"page_count": 5
```

### إخفاء كود من البرنامج بدون حذفه

غيّر:

```json
"status": "inactive"
```

ولإظهاره مرة أخرى:

```json
"status": "active"
```

### إضافة جهة مالكة للكود

مثال قبل:

```json
"applicable_owners": ["nwc"]
```

بعد:

```json
"applicable_owners": ["nwc", "makkah"]
```

## اختبار التعديل

بعد حفظ الملف:

1. افتح التطبيق.
2. اختر المشروع المناسب.
3. اختر الجهة المالكة المناسبة.
4. ابحث عن اسم الكود أو رقمه.
5. إذا ظهر الكود، فالربط صحيح.
6. اختر الكود.
7. اضغط بناء العرض الفني.
8. افتح ملف Word الناتج وتأكد من المحتوى.

---

## لو التطبيق لم يفتح بعد التعديل

غالبًا يوجد خطأ في JSON.

راجع هذه الأشياء:

1. هل نسيت فاصلة بين كودين؟
2. هل وضعت فاصلة بعد آخر كود؟
3. هل نسيت علامة اقتباس؟
4. هل كتبت اسم حقل خطأ؟
5. هل `code_id` يساوي اسم المفتاح؟

مثال صحيح:

```json
"003-PIP-MAIN": {
  "code_id": "003-PIP-MAIN"
}
```

مثال خطأ:

```json
"003-PIP-MAIN": {
  "code_id": "003-PIP-OTHER"
}
```

---

## قواعد ذهبية

1. لا تعدل أكثر من كود في نفس الوقت إذا كنت مبتدئًا.
2. اختبر بعد كل كود جديد.
3. لا تحذف كودًا قديمًا؛ اجعله `inactive`.
4. لا تغير أسماء الحقول.
5. لا ترفع ملفات Word حساسة إلى GitHub.
6. استخدم `نسخة_على_GitHub.bat` بعد نجاح التعديل.

---

## طريقة عمل آمنة من البداية للنهاية

1. شغّل `نسخة_على_GitHub.bat`.
2. افتح `codes_registry.json`.
3. انسخ كودًا مشابهًا.
4. غيّر `code_id` والاسم والمشاريع والجهات.
5. احفظ الملف.
6. افتح التطبيق.
7. جرّب ظهور الكود.
8. ابنِ عرضًا تجريبيًا.
9. إذا كل شيء صحيح، شغّل `نسخة_على_GitHub.bat` مرة أخرى.

هذه هي المنهجية المتكاملة الآمنة.
