## 1. الخلاصة التنفيذية

ATPAS هو تطبيق سطح مكتب Windows مبني بـ Python و PyQt5، يسهّل على مهندسي العروض الفنية في شركة الرواف بناء عروض Word فنية من خلال اختيار:

1. نوع المشروع.
2. الجهة المالكة.
3. الأكواد الفنية.

ثم يقوم النظام بالتحقق من التبعيات وبناء ملف Word جاهز للتقديم.

**الوضع الفعلي الحالي من ملفات النظام:**

| البند | القيمة الحالية |
|---|---:|
| الأكواد في `codes_registry.json` | 65 |
| الأكواد النشطة | 65 |
| أنواع المشاريع | 6 |
| الجهات المالكة في `master_config.json` -> `owner_specifications` | 20 |
| الأنماط الجاهزة في `presets.json` | 11 |
| الاختبارات المجمعة (`pytest --collect-only`) | 498 |
| تغطية engine+utils | 84% (بوابة CI: 75%) |
| الإصدار | v3.2 (من version.json) |
| فهرس الأرشيف | منفذ (`utils/archive_index.py` — SQLite/WAL) |
| الواجهة | PyQt5 عربية RTL |
| ملف التشغيل | `dist/ATPAS/ATPAS.exe` |
| البناء | `pyinstaller atpas.spec --noconfirm --clean` أو `build_exe.bat` |

### أهم فجوات الوصول إلى 9.5+

1. **اختبارات واجهة مصورة:** التقاط صور للشاشات الرئيسية لمنع رجوع مشاكل RTL والألوان.
2. **مكتبة محتوى حقيقية:** كل كود مهم يجب أن يرتبط بملف Word فعلي لا placeholder.
3. **توسيع إدارة الأكواد:** إضافة استيراد دفعات، مراجعة قبل الحفظ، وإظهار أثر التعديل على presets.
4. **توسيع تقرير صحة النظام:** تم تصدير Markdown، والخطوة التالية هي إضافة HTML/PDF وتقارير مقارنة بين النسخ.
5. **نسخ احتياطي واضح:** قبل أي تعديل واسع على الأكواد أو الجهات.
6. **توثيق حي محدث:** هذا الملف هو نقطة البداية، ولا يعتمد أي وكيل على ذاكرة المحادثة.

## 3. قاعدة الفهم لأي وكيل AI

إذا كنت وكيل ذكاء صناعي تعمل على ATPAS:

1. إذا بدأت من جذر المشروع، اقرأ `AGENTS.md` ثم هذا الملف.
2. اقرأ `docs/NON_TECH_CODE_WORKFLOW_AR.md` قبل تعديل الأكواد أو شرحها للمستخدم.
3. لا تعدل ملفات مخرجات مثل `dist/`, `build/`, `output/`.
4. لا ترفع ملفات عميل حقيقية أو ملفات Word حساسة إلى GitHub.
5. لا تغيّر أسماء الحقول في JSON إلا إذا عدلت المحرك والاختبارات والدليل.
6. بعد أي تعديل واجهة، شغل التطبيق أو التقط لقطة تحقق إن أمكن.
7. بعد أي تعديل جوهري، شغل `python -m compileall` على الملفات المعدلة على الأقل.
8. قبل الدفع إلى GitHub، راجع `git status --short`.

## 5. بنية النظام

```text
المستخدم
  ↓
واجهة PyQt5 عربية RTL
  ↓
اختيار مشروع + جهة + أكواد
  ↓
Validator: يفحص التوافق والتبعيات
  ↓
DependencyResolver: يقترح الأكواد الناقصة
  ↓
Builder: يجمع محتوى Word
  ↓
StyleApplier: يطبق نمط الجهة المالكة
  ↓
output/generated_documents/*.docx
```

## 6. نظام الأكواد

صيغة الكود القياسية:

```text
NNN-PHASE-VARIATION
```

مثال:

```text
001-SUR-BASE
```

المعنى:

| الجزء | مثال | المعنى |
|---|---|---|
| `001` | `001` | الفئة الرئيسية |
| `SUR` | Survey | مرحلة أو نوع النشاط |
| `BASE` | Base | تنويع أو نسخة النشاط |

الفئات الحالية:

| الفئة | المعنى |
|---|---|
| `001` | الأعمال التحضيرية |
| `002` | الحفر والمخلفات |
| `003` | التركيب والتوصيل |
| `004` | الاختبارات والفحوصات |
| `005` | الإنهاء والتسليم |

## 7. الحقول المطلوبة لكل كود

كل كود داخل `codes_registry.json` يجب أن يحتوي على هذه الحقول على الأقل:

```json
{
  "code_id": "001-SUR-BASE",
  "category": "001",
  "phase": "SUR",
  "variation": "BASE",
  "activity_name_ar": "مسح وتثبيت نقاط عامة",
  "activity_name_en": "General Surveying",
  "project_ids": ["wastewater"],
  "network_types": ["S"],
  "applicable_owners": ["nwc"],
  "sequence_order": 1,
  "dependencies": [],
  "page_count": 5,
  "status": "active"
}
```

قاعدة ذهبية: `code_id` داخل المفتاح يجب أن يساوي قيمة الحقل `code_id`.

## 8. طريقة إضافة كود باختصار

للتفصيل الكامل راجع:

```text
docs/NON_TECH_CODE_WORKFLOW_AR.md
```

الملخص:

1. خذ نسخة احتياطية أو شغل `نسخة_على_GitHub.bat`.
2. أضف الكود إلى `codes_registry.json`.
3. إن كان للكود محتوى حقيقي، ضع ملف Word باسم `{CODE_ID}.docx` داخل `templates/source_documents/`.
4. شغل التطبيق وتأكد أن الكود يظهر بعد اختيار المشروع والجهة.
5. ابنِ عرضًا تجريبيًا.
6. ارفع التغيير إلى GitHub.

## 11. قواعد الواجهة والتصميم

السياق التصميمي في:

```text
.impeccable.md
```

الاتجاه المعتمد:

```text
Luxury Industrial — احترافي، دقيق، موثوق
```

قواعد لا تكسرها:

1. التطبيق عربي RTL أولًا.
2. أي عنوان داخل `QGroupBox` يفضل أن يكون `QLabel` داخليًا، لأن عناوين Qt العائمة سببت قصًا وتشوهًا.
3. عند خلط عربي وإنجليزي داخل HTML أو QLabel، افصل الإنجليزي بصريًا أو اجعل اتجاهه LTR فقط.
4. لا تستخدم ألوانًا ضعيفة على خلفيات داكنة.
5. لا تضف حركة إلا إذا كانت توضح حالة أو نجاحًا أو خطأ.

## 12. سجل تحسينات واجهة حديثة

تمت معالجة المشاكل التالية في الجولات الأخيرة:

1. وضوح نصوص نافذة إضافة كود مخصص.
2. محاذاة أسماء الأكواد العربية يمينًا.
3. توحيد ألوان الحوارات والرسائل.
4. إضافة شاشة إعدادات بسيطة.
5. تحسين رسائل نجاح/خطأ.
6. إصلاح عناوين:
   - اختيار المشروع والجهة المالكة.
   - الأكواد المتاحة.
   - الأكواد المختارة.
   - التحقق والتحذيرات.
7. إصلاح محاذاة نافذة المساعدة والتبويبات العربية.
8. **حل جذري لمشكلة الانهيار (Crash):** استخدام مؤقتات مرتبطة بدورة حياة الوجت (Context-Aware Timers).
9. **تحول التصميم الشامل:** اعتماد خط **Tajawal** كخط أساسي موحد لكل البرنامج.
10. **تحسين الأداء (Anti-Flicker):** تجميد تحديث الواجهة برمجياً أثناء بناء قوائم الأكواد الضخمة.
11. **هيكلة التصميم (SSOT):** ترحيل كافة قيم الألوان والخطوط لملف `theme.py`.

### لمسات الإتقان التشغيلية

أضيفت طبقة تشغيلية خفيفة لكنها عالية الأثر:

1. شريط حالة أكثر ذكاءً يعرض عدد الأكواد والصفحات والتحذيرات.
2. زر `آخر عرض` في الهيدر لفتح أحدث ملف Word.
3. مؤشر `بلا Word` في قائمة الأكواد عند نقص ملف المحتوى.
4. بطاقة `جاهزية التسليم` داخل لوحة المراجعة.
5. تصدير تقرير الصحة إلى Markdown وHTML وPDF.
6. سجل نشاط داخلي في `output/reports/activity_log.json`.
7. زر `معاينة هيكل العرض` قبل البناء.
8. تحذير صريح قبل البناء عند نقص ملفات Word.
9. تعريب أزرار الحوارات الصغيرة مثل `حفظ` و`إلغاء`.
10. صفحة `عن النظام` تعرض الإصدار والصحة وآخر عرض وآخر نشاط.

## 14. ماذا لا تفعل

1. لا تحفظ ملفات Word حقيقية حساسة في GitHub.
2. لا تعدل `dist/` أو `build/` يدويًا.
3. لا تغير صيغة الكود بدون تحديث المحرك.
4. لا تضيف كودًا بدون `project_ids` و `applicable_owners`.
5. لا تعتمد على لقطة شاشة فقط؛ افحص الكود والملفات.
6. لا تعتبر `metadata.total_codes` وحده مصدر الحقيقة؛ عدّ الأكواد من `codes`.

ملاحظة مهمة: لا يوجد مفتاح باسم `owners` في `master_config.json`. مصدر الجهات المالكة الصحيح هو:

```text
master_config.json -> owner_specifications
```
